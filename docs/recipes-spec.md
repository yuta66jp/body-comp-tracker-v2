# 1食分の料理登録仕様

対象: Issue #788。目的は、よく作る料理の材料を毎回選び直さず記録すること。
「1食」は料理ごとの基準量（1人前）を示す。

## 食品データベース `/foods`

食品マスタ、料理、セットメニューの順に表示し、料理の登録・編集も同じページで行う。
既存の食品・セットの仕様は変更しない。料理をセットへ含める機能は対象外。

- 料理一覧は名前順・名前検索。料理名、1食分のカロリー・PFC、材料数を表示する。
- 詳細で材料・1食分の使用g数・任意メモを確認できる。
- 新規、編集、複製、非表示、復帰を提供する。通常一覧と食事入力には有効な料理だけを表示する。
- 非表示の料理はチェックボックスで表示し復帰できる。登録件数・非表示件数を表示する。摂取回数や最終摂取日は記録しない。
- 料理名は前後空白を除き必須。同一ユーザーでは非表示を含め一意。
- 材料は登録済み食品から1品以上。調味料・市販商品も利用できる。g数は正の小数を許容。同じ食品の追加は量を合算する。
- 料理の栄養値は自動計算し、直接入力・上書きしない。食品側のカロリー・PFCが欠けている場合は材料として追加できない。
- 材料の選び直しは、一度外して食品一覧から追加する。同じ材料を追加し直す場合も最新の食品情報を取り込む。
- フォームのキャンセルでは保存しない。保存失敗は入力内容を保持する。

### 材料情報の保持

料理定義は `recipe_master` にユーザーごとに保存する。材料は食品名、1食分のg数、100gあたりカロリー・PFCを保持し、食品への外部キーは持たない。
元食品の変更・削除で料理の値は変わらず、使用量変更は保持値で再計算する。複製も元料理の材料情報を引き継ぐ。
Server Actionでは新規材料を所有者の食品情報と照合する。材料選択から保存までに食品情報が変更・削除された場合は選び直しを案内する。
保存済み材料を使用する編集・複製は所有者の料理情報と照合する。競合する編集・非表示操作は更新日時で検出し、再読み込みを案内する。

## ダッシュボード `/` の食事入力

PCモーダル・スマートフォンシートとも「単品／料理／セット／一時」のタブを提供する。
料理一覧は名前順・名前検索に対応し、料理名と1食分のカロリー・PFCを表示する。一覧のボタンから1食追加できる。
未登録と取得失敗を区別する。取得失敗時は再試行できる。

- カートでは料理名と食数の1行で表示。0.5食・1.5食など正の小数を入力できる。
- 材料・メモは参照のみ。食数不正のまま日次保存できない。
- 同じ料理・同じ内容の再追加は食数を加算する。編集前後で内容が変わった料理は別行として保持する。
- 料理1行を1品と数え、カロリー降順に表示する。単品で追加した同名材料は別の摂取分として合算する。
- カートの料理を削除しても料理定義は削除されない。

### 栄養計算

材料ごとに `100gあたり栄養値 × 使用g数 ÷ 100` を求める。
材料を合計して食数を掛けた後、料理1行のカロリー・PFCを整数に四捨五入する。
丸め前の値から毎回計算する。既存単品・一時食品の計算は変更しない。

### 日次保存

- カート全体の合計で日次栄養値を置換する。既存値への加算ではない。
- 食事未操作なら既存値を保持し、追加後全削除は全NULLに戻す。0 kcal保存不可の既存ルールを維持する。
- 料理名・食数・材料明細は日次記録に保存しない。再訪時は日次合計だけを参照表示し、カートを復元しない。
- 保存成功時は既存どおり入力をリセットして閉じる。失敗時は入力を保持する。
- 料理定義の登録・編集・非表示・復帰によって日次ログは更新しない。

## その他のページ

ダッシュボード集計、栄養分析 `/macro`、履歴 `/history`、TDEE `/tdee`、予測精度 `/forecast-accuracy` は保存済み日次合計を従来どおり使用する。
設定 `/settings` に料理専用設定は追加しない。既存のエクスポート形式も変更しない。

## 対象外

カートからの料理作成、今回だけ材料変更、料理を含むセット、作り置きの重量管理、入れ子レシピ、URL・画像取り込み、共有、料理定義エクスポート。

## DB反映

`20260906000000_create_recipe_master.sql` は料理用テーブル・材料検証関数・更新日時トリガー・所有者RLSだけを追加する。既存食品・セット・日次記録のデータ更新はない。
アプリの料理機能を利用するには、このマイグレーションの適用が必要。未適用・取得失敗時は料理欄にエラーを表示し、既存食品・セットは使用できる。

## 検証

`supabase/tests/recipes.test.sql` はローカルDBで実行し、所有者権限、制約、スナップショット、非表示・復帰を検証してロールバックする。

実画面の書き込み検証は `E2E_RECIPE_TESTS=true npx playwright test e2e/recipes.spec.ts` で実行する。
`NEXT_PUBLIC_SUPABASE_URL` はローカルSupabaseに限定し、対応する公開キー、`ALLOWED_AUTH_EMAIL`、`E2E_AUTH_EMAIL`、`E2E_AUTH_PASSWORD` を設定する。
テスト専用ユーザーの食品に、100gあたり100 kcal・P 20g・F 1g・C 0gの材料を用意し、その名前を `E2E_RECIPE_FOOD_NAME` に設定する。
この検証はPC・スマートフォン幅で料理の管理と食事保存を行い、2098年1月1日・2日の記録を使用する。テストデータは専用のローカルユーザーに残す。
